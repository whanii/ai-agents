## 오늘의 핵심 3가지
- **LLM은 암호분석 벤치마크에서 기존 공격 재현을 넘어 일부 새로운 취약 분석까지 제시했다.**
- **에이전트 도입은 성능 최적화보다 정책 집행, 신원 관리, 샌드박싱 같은 운영 통제와 함께 설계될 필요가 있다.**
- **과학 컴퓨팅과 로컬 추론 사례는 에이전트형 워크플로가 연구 개발과 실행 비용 구조에 직접 연결되고 있음을 나타낸다.**

## 핵심 요약
- CryptanalysisBench와 Prompt-Hacking-Resources는 LLM 보안 평가가 모델 능력 측정과 입력 조작 위협 모델링을 함께 다뤄야 함을 시사한다.
- Microsoft의 Agent Governance Toolkit은 OWASP Agentic Top 10을 운영 통제 관점에서 묶어 에이전트 보안 기준을 표준화하려는 접근이다.
- kekzl/imp는 특정 GPU 아키텍처에 맞춘 로컬 추론 최적화가 에이전트 실행 성능 경쟁의 한 축이 되고 있음을 보여 준다.

## 실무 적용 포인트
- 에이전트 도입 조직은 정책 집행, 제로트러스트 신원, 샌드박싱을 초기 아키텍처 요구사항에 포함해야 한다.
- LLM 서비스 운영자는 프롬프트 인젝션과 jailbreak 자료를 활용해 입력 조작 테스트와 방어 체크리스트를 정기적으로 갱신하는 편이 좋다.
- 연구 조직은 반복 코드 작성과 레거시 도구 개선을 에이전트에 맡기되 결과 검증과 실험 설계 책임은 분리해 운영해야 한다.
