에이전트 도구 항목은 과거 세션 재사용과 Unity 워크플로 자동화처럼 개발 연속성과 작업 루프 단축을 겨냥한다.

OpenAI와 Google 사례는 국가안보 감독과 검색 기반 학습처럼 AI 기능이 제도와 일상 플랫폼 안으로 들어가는 흐름을 드러낸다.

Executive Read

핵심 요약

  • llm-d-router와 vLLM은 모델 자체보다 요청 경로, 정책 적용, 추론 효율을 다루는 인프라 계층의 비중이 커지고 있음을 시사한다.
  • deja-vu는 임베딩이나 외부 모델 없이 로컬 기록을 색인해 에이전트 맥락 손실을 줄이는 실용적 접근을 제시한다.
  • Unity-MCP는 특정 개발 환경에 MCP와 CLI를 붙여 여러 에이전트에서 동일한 도구 호출을 활용하려는 방향을 보여준다.

Action Points

  • LLM 서빙 팀은 라우터 계층에서 부하 분산, 접근 제어, 요청 정책을 어디까지 중앙화할지 검토해야 한다.
  • 에이전트 도입 팀은 과거 작업 기록을 재사용할 수 있는 로컬 메모리 도구를 먼저 실험해 반복 설명 비용을 줄이는 방안을 점검할 수 있다.
  • Unity 기반 조직은 에디터 작업과 테스트를 에이전트 워크플로에 연결할 때 작은 기능 단위부터 자동화 범위를 정하는 편이 현실적이다.
